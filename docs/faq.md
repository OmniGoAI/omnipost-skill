# 常见问题

## 它和 xiaohongshu-mcp 是什么关系？要二选一吗？

不冲突。xiaohongshu-mcp 是一个平台做得很深的单平台 server；OmniPost 是多平台的一个入口，小红书只是其中一个。只发小红书，两个都行；要发多平台，OmniPost 不用一个平台配一个 server。

## 为什么桌面应用不开源，只开源 Skill？

桌面应用里是各平台的对接实现，平台改版就得跟着改，我们靠付费版养这件事。Skill、规则速查、示例、文档全部 MIT，你能看到 agent 会怎么调它、会读到什么。

## 免费版能让 agent 发吗？

目前通过 MCP / CLI 自动发布属于专业版功能；免费版可以在应用界面里发 8 个开发者平台。装好后在应用内一键领 7 天专业版试用，不填卡。

## 会被封号吗？

会有风险，任何自动化发布都有。小红书 2026 年 3 月的官方公告明确说 AI 托管的注册、发布、互动会被封禁。OmniPost 的做法是：默认进草稿箱、正式发布由你点、不自动互动、不模拟真人；`rules/` 里按平台列了官方红线让 agent 发前先读。多账号、高频、同质内容是封号主因，请降频、改写、人工确认。我们不说「防封」，谁说都别信。

## 登录态多久会掉？

由平台决定，不是 bug。实测微信公众号网页登录 3～4 天固定过期，CSDN / 掘金 / 知乎能活 1～2 个月。OmniPost 做三件事：到期前 12 小时预警；因登录失效没发出去的内容在你重登后自动补发（48 小时窗口）；`alerts` 一个接口把失效、将到期、待补发汇总给 agent，分发前先看一眼。

## 微信公众号能自动群发吗？

不能，也不打算做。网页版扫码登录只能建草稿（封面、裁剪都会自动做好），群发不可逆且有次数限制，由你在后台点。配置了已认证服务号 appId/appSecret 的 API 模式可以走「发表」接口（生成公开链接、不推送粉丝）。

## 支持视频吗？

支持。小红书、B站、视频号、抖音、快手、微博、百家号、搜狐号可发视频；`omnipost video-check` 先体检文件（只读文件头，不上传），`omnipost rehearse` 走到选文件前停下做彩排。抖音 / 快手 / 视频号 / 小红书正式发布时可能弹验证码或滑块，需要你在弹出的窗口里人工完成。

## 多账号怎么办？

同一平台可以登录多个账号，每个账号一个独立会话分区，物理隔离。发布时用 `--targets xiaohongshu:a,xiaohongshu:b`，或先 `omnipost group save 短视频组 --targets ...` 存成分组，之后 `--group 短视频组`。

## 我的数据去哪了？

全部在本机 `~/.omnipost/`：登录态、草稿、发布记录、定时任务。不上传凭据，不中转请求。匿名使用统计只有一个随机安装 ID 和事件计数，不含内容、账号、IP，可在应用内关闭。

## 支持 macOS / Linux 吗？

Windows 和 macOS（Apple Silicon）有安装包。Linux 暂无。

## 平台改版发不出去了怎么办？

开 issue，附 `omnipost posts --limit 5` 的结果和平台名。平台对接是我们的日常工作，改版通常几天内修。
